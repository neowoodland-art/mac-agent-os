# AgentOS 加载与检索架构

> 版本：v1.0 | 最后更新：2026-05-03
> 本文档描述 AgentOS 的四条独立加载/检索管道及其协作方式。

---

## 一、核心设计原则

> **不同类型的信息，用不同的方式加载。不混在一起，不相互干扰。**

```
行为控制层（身份+协议）→ 不走向量检索，靠注入和触发词
内容检索层（知识+记忆）→ 走向量检索，靠语义匹配
```

---

## 二、四管道架构

### 管道①：身份注入（常驻）

| 属性 | 值 |
|------|------|
| **文件** | SOUL.md + IDENTITY.md + USER.md |
| **存储** | `~/.workbuddy/` |
| **加载方式** | WorkBuddy 每次对话启动时自动注入 |
| **Token 占用** | ~750（常驻） |
| **是否走向量** | ❌ 不走向量检索 |
| **内容** | 行为规则、模式切换、安全边界、身份、用户画像 |

### 管道②：协议按需加载（触发词激活）

| 属性 | 值 |
|------|------|
| **文件** | meta-thinking.md / cross-domain.md / stuck-intervention.md / knowledge-review.md |
| **存储** | `03_knowledge/99_system/protocols/` |
| **加载方式** | SOUL.md 检测触发词后读取对应文件，执行完退出 |
| **Token 占用** | 每个 ~200（用完即退） |
| **是否走向量** | ❌ 不走向量检索（存放在 99_system/，不参与知识搜索） |
| **触发机制** | 当前：关键词匹配 → 可升级为语义相似度匹配 |

### 管道③：知识库语义检索（按需搜索）

| 属性 | 值 |
|------|------|
| **目录** | `03_knowledge/`（排除 99_system/） |
| **内容** | 概念知识 (10_concepts/)、方法论 (20_methods/)、参考资料 (40_references/) |
| **检索方式** | BM25 关键词 + ChromaDB 语义向量 + RRF 融合排序 |
| **向量模型** | Qwen3-Embedding-0.6B（1024 维） |
| **是否常驻** | ❌ 不常驻，用户提问时按需检索 |
| **负责技能** | kb_manager |

### 管道④：记忆系统分层检索（自动触发）

| 属性 | 值 |
|------|------|
| **目录** | `04_memory/` |
| **检索流程** | L1 → L2 → L3 分层截断 |
| **L1** | keyword_index.json + ChromaDB 向量 → 关键词+语义混合检索 |
| **L2** | facts.db（SQLite 结构化事实，置信度 ≥ 0.7 才返回） |
| **L3** | raw 原文存档（仅用户明确要求时才加载） |
| **截断规则** | L1 无匹配 → 停止；L2 置信度不足 → 不 fallback |
| **负责技能** | memory_manager |

## 三、数据流图

```
用户输入
    │
    ├─→ 管道①（身份注入已常驻）→ 行为规则已就位
    │
    ├─→ SOUL.md 检测触发词
    │     ├─ 命中 → 管道②：加载对应协议文件 → 执行 → 退出
    │     └─ 未命中 → 继续工程模式
    │
    ├─→ 用户询问知识 → 管道③：BM25+ChromaDB 检索知识库
    │
    └─→ 用户提问触发记忆 → 管道④：L1→L2 分层检索
```

---

## 四、Token 优化策略

| 策略 | 实现 | 节省效果 |
|------|------|---------|
| 分层截断 | L1 无匹配立即停止 | 避免整库扫描 |
| 置信度阈值 | L2 < 0.7 不返回 | 避免低质量事实占用 context |
| 协议退出 | 协议文件用完即退出上下文 | 每个协议 ~200 tokens 不持续占用 |
| L3 延迟加载 | 仅用户明确要求才加载 | 最大节省（原文通常很大） |
| 按需加载 | 知识库检索只返回片段 | 避免全文件读取 |
| 99_system 排除 | 系统文档不参与向量检索 | 减少搜索噪音 |
