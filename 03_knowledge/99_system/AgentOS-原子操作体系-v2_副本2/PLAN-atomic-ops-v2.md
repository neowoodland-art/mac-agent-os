## 一、核心理念

### 1.1 我们不是在写代码，是在建立一套"自动化操作知识库"

每个平台的每个操作，都应该像一本字典里的词条：
- 有明确的"前提条件"（在什么页面/状态下才能做）
- 有确定的"执行方式"（用什么方法做）
- 有可验证的"结果"（做了之后页面变成什么样子）

### 1.2 不做"按键精灵"，做"智能操作代理"

按键精灵: 盲按 → 不管结果 → 继续按下一个
智能代理: 检测当前状态 → 确认可以操作 → 执行 → 验证结果 → 记录

### 1.3 开发效率 > 代码量

一次录制 = 10个原子操作的新代码，比你手写10个函数快100倍。
但前提是：录制系统能捕获足够的信息（状态+操作+结果），并且你我能高效标注它。

## 三、PageState 状态模型（引擎层核心）

### 3.1 抖音页面状态定义

| 状态名 | 判断条件 | 可用操作 |
|:------|:---------|:---------|
| `grid` | URL含jingxuan，card_count>0 | scroll_feed, open_video, search, goto_profile |
| `player_modal` | URL含modal_id，video>0 | like, collect, follow, comment, next_video, go_back |
| `player_full` | URL含/video/xxx | like, collect, follow, comment, go_back |
| `search` | URL含/search/ | click_result, scroll, go_back |
| `profile` | URL含/user/ | read_field, go_back |

### 3.2 小红书页面状态定义

| 状态名 | 判断条件 | 可用操作 |
|:------|:---------|:---------|
| `grid` | URL=/explore, note-item>0 | scroll_feed, click_note, search, goto_profile |
| `note_detail` | URL=/explore/xxx | like, collect, comment, post_comment, follow, go_back |
| `search` | URL=/search_result | click_result, go_back |
| `profile` | URL=/user/profile/xxx | read_field, go_back |

### 3.3 状态转换规则

```
grid ──(open_video/click_note)──> player/note_detail
grid ──(search)──────────────────> search
grid ──(goto_profile)────────────> profile
player ──(go_back)───────────────> grid
player ──(next_video)────────────> player (不同视频)
search ──(click_result)──────────> player/note_detail
search ──(go_back)───────────────> grid
profile ──(go_back)──────────────> grid
```

### 4.2 录音交互流程

```
1. 你启动录制: mc record --account=douyin_test --platform=douyin
   → 浏览器打开，开始录制

2. 你做操作，按 `·` 标记每一步
   → 系统自动捕获 before/action/after

3. 录制结束按 Esc
   → 系统保存完整录制数据

4. 进入标注界面（Dashboard新页面）
   → 展示每一步的 before/action/after
   → 自动检测操作类型（点击/按键/滚动）
   → 自动建议原子操作名称（like/collect/comment）
   → 你可以修改名称和补充说明
   → 连续2步可以合并为1个原子操作（如：开评论(x) + 输入 + 发送 = post_comment）

5. 标注完成 → 系统自动生成原子操作代码模板
   → 你审核通过 → 代码入库
```

## 五、单步调试模式（工具层）

### 5.1 命令设计

```bash
# 模式1: 启动交互式调试（浏览器保持打开）
mc debug --accounts=douyin_test --platform=douyin
  → 浏览器打开，保持运行
  → 等待命令

# 模式2: 执行单步操作
mc step open_video          # 只执行这一个操作，返回结果+消耗时间
mc step like                # 继续下一步
mc step collect             # 3秒内出结果

# 模式3: 批量单步（自动但不跳过）
mc step open_video like collect follow open_comments post_comment
  → 每步执行后停顿1秒，显示结果，继续下一步
```

### 5.2 交互流程

```
> mc debug --accounts=douyin_test
✅ 浏览器已启动，当前状态: grid (首页)
等待命令...

> open_video
✅ open_video → video_detail (5.2s) 状态: grid → player_modal
验证: video=1 ✅ 可继续下一步

> like
✅ like → 👍 (1.1s) 状态: player_modal
验证: 通过✅

> collect
❌ collect → - (0.0s) 状态: player_modal
元素未找到: [data-e2e="video-player-collect"]
回退: JS搜索也失败，坐标兜底也失败
建议: 你在浏览器里点一下收藏，我看看实际DOM是什么
```
