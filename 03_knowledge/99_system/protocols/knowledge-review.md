# 知识审查协议

> 文件：99_system/protocols/knowledge-review.md
> 触发词：入库、记录这条、保存知识、知识审查
> 加载方式：SOUL.md 检测触发词后加载

---

## 审查四步

### 第一步：来源可靠性评分

| 来源类型 | 评分 | 
|---------|------|
| 官方文档 / 学术论文 | +0.3 |
| 知名技术博客 / 行业报告 | +0.1 |
| 个人博客 / 论坛帖子 | -0.1 |
| 未知来源 / 社交媒体 | -0.3 |
| **基础可靠性基线** | **0.5** |

### 第二步：一致性检查

与 L2 已有事实对比：
- **完全一致** → 旧知识 confidence 轻微提升
- **补充细节** → 合并为新条目
- **矛盾** → 进入冲突消解（新事实 > 旧事实，用户明确修正 > 系统推断）

### 第三步：时效性标记

| 知识类型 | 有效期 |
|---------|--------|
| 技术类知识 | 180 天后自动失效 |
| 法律/法规 | 按原文有效期 |
| 个人偏好/观点 | 不过期，标记为 opinion |
| 物理/数学公理 | 永久有效 |

### 第四步：日志记录

写入 kb_ingest.log，格式：
`{timestamp} | {kb_id} | {decision} | {reason} | {confidence}`

## 知识版本管理

| 变化类型 | 处理方式 |
|---------|---------|
| 硬事实改变（如 4C8G → 8C16G） | 更新原卡片，旧值写入 previous_version |
| 软升级（V1→V2，V1仍有价值） | 保留 V1，新建 V2，related 链接 |
| 观点→事实 | nature 改为 fact，confidence 提升 |

---

## 自学习规则

- 所有错误写入 errors.log
- 用户纠正时触发修补：事实错误→更新 L2 facts.db，方法错误→更新方法卡片，观点分歧→标记 opinion
- 同一类型错误出现 3 次 → 触发技能改进建议

---

## 输出

审查通过后确认入库路径，汇报决策和理由，一行总结。
