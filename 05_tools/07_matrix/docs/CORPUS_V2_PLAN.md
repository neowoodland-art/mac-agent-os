# 语料库架构升级方案 v2.0

> 作者: ghai | 日期: 2026-06-13 | 状态: 方案阶段

---

## 一、当前架构（v1.x）的问题

```
语料库 = 分类 → 评论列表
  │
  ├─ 赞美: ["讲得太好了", "学到了"]
  ├─ 搞笑: ["哈哈哈哈哈"]
  └─ 提问: ["请问这是哪里？"]
```

**局限：**
1. 只有**态度语气**维度（赞美/搞笑/客观），没有内容维度（科技/美食/养生）
2. 没有**人设/身份**维度（以什么"人"在说话）
3. 没有**多轮交互**（第一次说啥、第二次说啥）
4. 没有**故事线/IP**绑定（围绕某个话题展开）
5. 无法表达复杂评论（带逻辑的、有结构的）

---

## 二、目标架构（v2.0）

### 三维语料模型

```
语料 = 身份(Persona) × 场景(Scene) × 内容(Content)

身份(Persona):    谁在说话
  ├─ 养生爱好者     → "小美养生茶" 这个号的人设
  ├─ 科技极客       → 说话带专业术语
  ├─ 美食探店达人   → 语气活泼，爱用表情
  └─ 情感博主       → 感性、共情

场景(Scene):      在什么情境下说话
  ├─ 初次评论       → 第一印象
  ├─ 跟帖回复       → 对别人评论的回应
  ├─ 作者回复       → 博主回复粉丝
  └─ 故事线对话     → 多轮剧情互动

内容(Content):    具体说什么
  ├─ 模板句         → "这个{keyword}太棒了"
  ├─ 故事片段       → "我曾经也遇到过..."
  ├─ 知识补充       → "其实{keyword}的原理是..."
  └─ IP台词         → 某个IP的经典语录
```

### 数据结构

```yaml
# corpus/douyin.yaml v2.0
version: "2.0"

# ── 身份配置 ──
personas:
  health_lover:
    name: "养生爱好者"
    tags: ["养生", "健康", "中医"]
    style: "温和、专业"
    rules:
      - "不提西医西药"
      - "多用'调理'代替'治疗'"
  
  tech_geek:
    name: "科技极客"
    tags: ["数码", "AI", "编程"]
    style: "理性、数据驱动"

# ── 场景配置 ──
scenes:
  first_comment:           # 首次评论
    label: "首次评论"
    rounds: 1              # 1轮
    rules:
      - "不要提到自己"
      - "与视频内容相关"
  
  follow_up:               # 跟帖回复
    label: "跟帖回复"
    rounds: 2              # 最多2轮
    rules:
      - "先认同对方观点"
      - "再补充自己的看法"
  
  story_arc:               # 故事线
    label: "故事线对话"
    rounds: 3-5            # 3-5轮
    rules:
      - "每轮推进剧情"
      - "保持角色一致性"
  
  author_reply:            # 作者回复粉丝
    label: "作者回复"
    rules:
      - "先感谢评论"
      - "针对评论内容回应"

# ── 内容库 ──
content:
  health_lover:
    first_comment:
      - "这个养生方法很实用，我也在坚持"
      - "中医讲究辨证论治，不能一概而论"
      - "食疗比药疗更温和，推荐大家试试"
      - "{keyword}这个方法确实有效，亲测"
    
    follow_up:
      round_1:
        - "确实如此，{keyword}我也是这么认为的"
        - "同意，不过还要注意个体差异"
        - "你说得对，我再补充一点..."
      round_2:
        - "对，我之前也遇到过同样的情况"
        - "是的，后来我换了一种方法就好了"
    
    author_reply:
      - "谢谢你的评论，{keyword}确实是个好问题"
      - "感谢支持，我会继续分享更多{keyword}的内容"

  tech_geek:
    first_comment:
      - "这个技术方案在性能上还有优化空间"
      - "从架构角度看，{keyword}这个方案更合理"
      - "数据支撑不够，建议补充A/B测试结果"

# ── IP/故事线 ──
ip_stories:
  douyin_hot_series:
    name: "抖音热评系列"
    scenes:
      intro:
        - "最近{keyword}这个事我也关注了"
        - "看了好几遍，说说我的看法"
      develop:
        - "其实这个事情要从几个方面看..."
        - "很多人忽略了最关键的一点..."
      climax:
        - "最让我震撼的是..."
        - "这个案例告诉我们..."
      ending:
        - "总的来说，{keyword}给了我们很多启示"
        - "希望以后能看到更多这样的内容"
```

## 三、执行链路

```
用户输入：评论指令
  │
  ├─ 1. 解析上下文
  │   ├─ 当前账号 → 获取 Persona（养生爱好者/科技极客）
  │   ├─ 当前场景 → 首次评论/跟帖回复/作者回复
  │   └─ 视频标题 → 提取关键词
  │
  ├─ 2. 选择语料
  │   ├─ content.{persona}.{scene} → 匹配模板
  │   ├─ 关键词替换 {keyword}
  │   ├─ 多轮计数（round_1/round_2）
  │   └─ fallback → AI 生成
  │
  ├─ 3. 发送评论
  │   └─ pbcopy + Meta+V + Enter
  │
  └─ 4. 记录上下文
      ├─ 已发送评论内容
      ├─ 当前轮次（用于多轮）
      └─ 下次回复策略
```

## 五、实施路线

| 阶段 | 内容 | 工作量 |
|------|------|--------|
| Phase 1 | 语料库 YAML 格式升级（v1→v2） | 2天 |
| Phase 2 | CorpusManager 升级（支持身份/场景/多轮） | 2天 |
| Phase 3 | Dashboard 语料管理页面升级（三维管理） | 3天 |

- `@corpus` 占位符继续保持可用
- 新增 `@persona`、`@scene` 占位符支持
- CorpusManager.get_comment_for_video() 参数不变，内部升级
