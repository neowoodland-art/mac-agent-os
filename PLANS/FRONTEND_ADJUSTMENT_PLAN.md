### 2.2 定向评论（matrix-comment.js）— ❌ 需要大改

**当前问题**：
1. 只支持 `type:'comment'`，不支持 `smart_comment`
2. 没有视频分析预览 — 填了链接直接执行，用户不知道会发什么评论
3. 语料选择只有硬编码的下拉（"通用/科技/生活/美食/娱乐"），不反映后端实际的行业池
4. 每个视频×每个账号发一次 `/ops/run`，效率低（N 个账号×M 个链接 = N×M 次 API 调用）

**需要改为**：

```
┌───────────────────────────────────────────────────┐
│ 💬 智能评论（新版）                                  │
│                                                      │
│  [账号选择器]                                       │
│                                                      │
│  视频链接: [textarea 每行一个]                       │
│                                                      │
│  方向: [称赞/提问/共鸣/感慨]  语料: [自动/行业/万能] │
│                                                      │
│  [▶️ 分析视频] [▶️ 直接执行]                        │
│                                                      │
│  ── 分析结果预览 ──                                  │
│  url1 → [health] "医生讲得很清楚..."     [✏️ 修改]   │
│  url2 → [general] "博主说得很对..."      [✏️ 修改]   │
│  url3 → [health] "这个方子很实用..."     [✏️ 修改]   │
│                                                      │
│  全部 3 个视频分析完成，预计分发 20 个账号            │
│  [✅ 确认并分发]                                     │
└───────────────────────────────────────────────────┘
```

**具体改动**：
| 改动 | 说明 | 工作量 |
|:-----|:------|:-------|
| 新增分析按钮 + 预览区 | 先调 `smart_comment` 只分析不分发，返回预览 | ~80行 |
| 预评论可编辑 | 用户可在预览区修改每条评论后确认 | ~30行 |
| 行业标签显示 | 每个视频分析后显示 `[health]` 或 `[general]` 标签 | ~10行 |
| 语料下拉从后端动态加载 | 从 `/matrix/corpus` 接口读取实际分类列表 | ~15行 |
| 批量提交 | 分析完的一次性 `POST /ops/run` 全部账号×全部URL | ~20行 |
| **合计** | | **~155行** |

## 四、smart_comment 前端交互流程

```
用户进入「定向评论」页面
    │
    ├─ 选择账号（账户选择器）
    ├─ 填写视频链接（textarea，每行一个）
    ├─ 选择方向（称赞/提问/共鸣）
    └─ 选择语料（自动/行业匹配/指定分类）
    │
    ▼
点击「分析视频」
    │
    ▼
前端调 POST /api/ops/run {type:"smart_comment", accounts: [只取1个], params:{urls, direction, preview:true}}
    ↓ 后端 VideoAnalyzer 分析
    ↓ 返回 {url: {title, industry, comment}}
    │
    ▼
前端显示分析结果预览
  ┌─────────────────────────────────────────┐
  │ url1 → [health] "医生讲得很清楚..."  [✏️]│
  │ url2 → [general] "博主说得很对..."   [✏️]│
  └─────────────────────────────────────────┘
  用户可逐条修改预评论
    │
    ▼
点击「确认并分发」
    │
    ▼
调 POST /api/ops/run {type:"smart_comment", accounts:[全部], params:{urls, direction, comments:{url:预评论}}}
    ↓
后端直接拆解 → 打包 → API 分发到各机 guardd
    │
    ▼
前端切换到指挥台，显示各机队列状态
```

## 五、预审/修改流程的关键设计

**关键设计点：用户在分发前可以看到并修改每条预评论**

```javascript
// 分析结果数据结构（前端存储）
let previewData = {
  urls: {
    "https://v.douyin.com/xxx": {
      title: "胃镜到底疼不疼",
      industry: "health",
      comment: "医生讲得很清楚，通俗易懂"  // 用户可编辑
    },
    "https://v.douyin.com/yyy": {
      title: "苏州美食探店",
      industry: "general",
      comment: "博主说得很对"              // 用户可编辑
    }
  }
};

// 用户编辑预评论后，确认分发
async function confirmDistribute() {
  // 收集所有预评论（含用户修改后的）
  const comments = {};
  for (const [url, data] of Object.entries(previewData.urls)) {
    comments[url] = data.comment;
  }
  // 一次性分发
  await apiRequest('/ops/run', {
    method: 'POST',
    body: JSON.stringify({
      type: 'smart_comment',
      accounts: selectedAccounts,
      params: { urls: Object.keys(comments), comments, direction }
    })
  });
}
```
